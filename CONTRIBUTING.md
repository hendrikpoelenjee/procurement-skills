# Contributing

Thanks for considering a contribution.

## How to contribute

- Open an issue for bugs, gaps, or proposal-level changes.
- For direct fixes, open a pull request with a clear summary and rationale.
- Keep skill contracts aligned (front matter, expected outputs, output contract, typical outputs).
- Preserve standards consistency across `skills/` and `standards/`.

## Quality expectations

- Keep changes minimal and focused.
- Update documentation when behavior, paths, or output names change.
- Avoid introducing conflicting contracts across skills.
- Prefer explicit, deterministic naming for artifacts.
